Done, and moved to `in review`; nothing is committed yet.

- The issue list has an **Opened** column between Assignee and State.
- Dates in the current year show the month and day, such as `Oct 11`. Dates in other years add the year, such as `Jun 4, 2023`, which is the format the issue view uses for bylines.
- The date comes from the issue's byline and is shown in the byline's own time zone, as in the issue view, so the list and the issue never disagree about the day.
- If a byline's date can't be read, the cell is left empty and the issue is still listed.
- The column is as wide as its longest date, and the title takes the remaining width.
- The four date formats bylines use were parsed by duplicated code in `Issue` and `Card`. That's now one `parseDate` helper, plus `Issue.Opened()`, which the list uses. Bylines render as before.
- Added tests for the date formats (this year, earlier years, another byline format, time zones and unreadable dates), the column's position, alignment and width, and `parseDate`.

Note for a possible follow-up issue: with five columns, an 80-column terminal leaves titles about 9 characters wide. The list could hide the Assignee or Opened column below some width.
