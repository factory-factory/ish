Use the git author attribuitions from commit logs to populate a table of display names and emails for users associated with the repository.

## SQLite user table

The user name and emails should be stored in an SQLite table in the `.metadata.ish` file maintained by the ish program.

The table requires the following fields:

- `id`: text (uuid4)
- `name`: text
- `email`: text

There should be a unique index on the `name,email` pair of columns, as well as indexes on the `name` and `email` columns individually.

## On `ish init`

When initializing an ish project, use `git log` to fetch a list of all contributors to the repository. The command `git log --all --format="%an <%ae>" | sort -u` lists each author's name and email across all commits. The `sort -u` deduplicates the list.

The list of authors should be parsed to split the name and email into an upsert query to store in the user table.

## All other times starting `ish`

On normal startups of `ish`, do a similar listing of authors, but limit it to the most recent 50 commits by using the `-n 50` flag to `git log`.

## The user table

- **Columns:** `id` (a version 4 UUID), `name` and `email`, all required.
- **Indexes:** a unique index on `(name, email)`, and indexes on `name` and on `email`.
- **Schema version:** it's now 3, so an existing database is rebuilt automatically the next time ish starts.

## Reading the git history

- **The command:** ish runs `git log --all` from the issue directory, so it finds the repository the issues are in.
- **The format:** I separate the name and email with a NUL character (`--format=%an%x00%ae`), rather than parsing `%an <%ae>`. A name can contain `<`, but it can't contain a NUL, so the split is always right.
- **Duplicates:** these are dropped in ish rather than with `sort -u`, keeping the order git lists them in.
- **Adding:** each user is added with `INSERT ... ON CONFLICT (name, email) DO NOTHING`, so a user already in the table keeps their ID.

## When users are indexed

- **On `ish init`:** the authors of every commit are added. `ish init` reports how many, for example "Indexed 1 user from the git history".
- **Every other start:** the authors of the 50 most recent commits are added (`-n 50`, also with `--all`). This is done quietly, like the rest of the start-up sync when nothing has changed. If it fails, the problem is reported, but ish still starts.
- **Without git:** if the issues aren't in a git repository, or git isn't installed, no users are added, and nothing fails.

## Testing

- **Parsing:** names containing `<…>`, duplicates, one name with two emails, blank and malformed lines, and an empty email.
- **`ish init`:** it asks git for every commit, adds each user once with a version 4 UUID, and reports the count.
- **Start-up:**
  - it asks git for the most recent 50 commits and adds only new users
  - existing users keep their IDs, and indexing again adds nothing
  - without git, nothing is added and nothing fails
- **The table:** the three indexes exist, and a duplicate name and email is rejected.
- **With a real git repository:**
  - `gitAuthors` lists every commit's authors, or just the latest commit's with a limit, and fails outside a repository
  - `ish init` reports two users, and the next start adds a third author quietly
